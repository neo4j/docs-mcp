= Migrate from v1 to v2
:description: Migrate a Neo4j MCP server from v1 to v2.

Neo4j MCP v2 includes breaking changes to configuration, HTTP requests, and requirement checks.
The environment variables and CLI flags removed in v2, together with the v1 behaviors described below, are no longer supported.

== Breaking changes

=== Configuration names changed

In v2, environment variables use the `NEO4J_MCP_` prefix to scope them to Neo4j MCP.
CLI flags are unscoped and use short names without the `--neo4j-` prefix.
Use these v2 names in every server configuration and client definition.
When both are set for the same option, the CLI flag takes precedence over the environment variable.

=== HTTP endpoint includes the database

The v1 endpoint was:

[source,bash]
----
POST https://example.com/mcp
----

In v2, include the target database name in the URL:

[source,bash]
----
POST https://example.com/db/neo4j/mcp
----

Trailing slashes are tolerated.
The `/mcp` path no longer exists and returns `404`.
Non-`POST` and non-`OPTIONS` methods return `405`.
Invalid database names return `400`.

For example, change an HTTP client configuration from:

[source,json]
----
{
  "type": "http",
  "url": "https://example.com/mcp"
}
----

to:

[source,json]
----
{
  "type": "http",
  "url": "https://example.com/db/neo4j/mcp"
}
----

=== HTTP mode is multi-tenant

In v1, an HTTP server could be configured with a single URI and database at startup.
In v2, HTTP mode selects the Neo4j instance and database for each request.

Do not set `NEO4J_MCP_URI`, `NEO4J_MCP_USERNAME`, `NEO4J_MCP_PASSWORD`, or `NEO4J_MCP_DATABASE` in HTTP mode.
The server refuses to start if these options are set.
The URI error is:

----
Neo4j URI should not be set for HTTP transport mode; URI is provided per-request via X-Neo4j-MCP-URI header
----

The database error is:

----
NEO4J_MCP_DATABASE … should not be set for HTTP transport mode; database is selected per-request via URL path
----

Every request must include the `X-Neo4j-MCP-URI` header.
Credentials must be supplied per request using Basic authentication or a Bearer token.
See xref:http-mode.adoc[] for the complete HTTP request reference.

For example:

[source,http]
----
POST /db/neo4j/mcp HTTP/1.1
Host: example.com
X-Neo4j-MCP-URI: bolt+s://instance.example.com
Authorization: Basic BASE64_ENCODED_CREDENTIALS
----

=== STDIO requires an explicit database

The v1 STDIO default database was `neo4j`.
In v2, set `NEO4J_MCP_DATABASE` or use `--database` explicitly.
Otherwise startup fails with:

----
Neo4j database is required for STDIO mode (set NEO4J_MCP_DATABASE or use --database flag)
----

For example:

[source,json]
----
{
  "type": "stdio",
  "command": "neo4j-mcp",
  "env": {
    "NEO4J_MCP_URI": "bolt://localhost:7687",
    "NEO4J_MCP_USERNAME": "neo4j",
    "NEO4J_MCP_PASSWORD": "password",
    "NEO4J_MCP_DATABASE": "neo4j"
  }
}
----

=== Requirement checks run at initialize

In v1, connectivity, query execution, and APOC checks ran as startup pre-flight checks.
In v2, these checks run when the MCP `initialize` request is processed.
The `initialize` request fails with a descriptive error if the database is unreachable, the configuration is invalid, or APOC is missing.
APOC must be installed and include the `meta` component.

The `list-gds-procedures` tool is enabled by default and is no longer auto-detected from GDS presence.
When that tool is enabled for a request, v2 verifies GDS with `gds.version()`.
If GDS is absent, that check is non-fatal and `initialize` still succeeds.
See xref:requirement-checks.adoc[].

== Additions in v2

=== Tool filtering

Server-level tool filtering is available with `NEO4J_MCP_TOOLS` or `--tools`.
Per-request HTTP tool filtering is available with `X-Neo4j-MCP-ReadOnly` and `X-Neo4j-MCP-Tools`.
See xref:tools.adoc#_tool_filtering[Tool filtering].

=== Request timeout

MCP requests, including tool calls and `initialize`, now have a timeout.
Configure the server limit with `NEO4J_MCP_REQUEST_TIMEOUT` or `--request-timeout`.
HTTP clients can set `X-Neo4j-MCP-Request-Timeout` to use a lower limit for one request.
See xref:configuration.adoc#request-timeout[Request timeout] and xref:http-mode.adoc[].
